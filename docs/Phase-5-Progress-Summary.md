## 원 계획 대비 변경된 결정사항

### 사이드바는 전 역할 공통 노출, 조회 권한만 다름

처음엔 "매니저/dev 화면에만 사이드바가 있다"고 오해하고 구현했으나, "운영진과 학생의 차이는 그 인원의 일정을 조회할 수 있냐 없냐지, 사이드바의 유무가 아니다"라는 정정이 있어 TODO/학생/팀 탭 모두 모든 역할에 노출하는 구조로 바로잡음. 학생이 자기 아닌 다른 사람을 선택하면 실제로 전환하지 않고 경고 메시지만 띄우고 본인 달력을 유지 — 백엔드가 `GET /schedules`에서 이미 403으로 막고 있어 프론트는 불필요한 왕복만 줄여주는 역할.

### 개인 "Team" 탭 제거 → 전체 "팀" 아코디언 탭으로 통합

처음엔 "내 팀 정보 + 팀원 목록만 보여주는 Team 탭"과 "전체 팀을 훑어보는 팀 탭"을 별도로 뒀는데, 후자가 전자를 완전히 포함하는 상위 집합(내 팀을 펼치면 동일한 정보 + 다른 학생 조회까지 가능)이라는 지적이 있어 전자를 제거하고 하나로 통합.

### `GET /users`를 전체 역할에 개방

"학생" 탭 전용으로 학생만 반환하던 `GET /users`를, 매니저/운영진/dev 구분 없이 전체 계정을 반환하도록 확장 — 디렉토리 자체는 누구나 볼 수 있고, 실제로 접근이 제한되어야 하는 건 "그 사람의 일정"뿐이라는 원칙에 맞춤. 이 결과 dev 전용으로 따로 있던 `GET /users/all`(계정 관리 화면용)이 완전히 중복되어 제거하고 하나로 합침.

### 한글 정렬을 SQL이 아니라 애플리케이션(Python)에서 처리

`ORDER BY nick_name`으로 가나다순 정렬을 기대했으나, DB 콜레이션(`en_US.utf8`)이 한글을 사전순으로 정렬하지 않는다는 게 테스트로 드러남. 한글 음절 유니코드 코드포인트 순서가 실제 가나다순과 일치한다는 점을 이용해, 정렬을 Python(`sorted()`)으로 옮겨 해결.

### rate limiting을 기본값으로 비활성화

기능은 유지하되(`RateLimitMiddleware` 코드는 그대로 존재) `RATE_LIMIT_ENABLED` 기본값을 `true → false`로 전환. 관련 테스트 2개는 삭제하지 않고 `pytest.mark.skipif`로 스킵 처리해 기능이 다시 필요해질 때 그대로 살릴 수 있게 함.

## 트러블슈팅 (실사용 중 발견된 버그 포함)

- **refresh 쿠키가 브라우저 새로고침마다 사라짐.** Vite 프록시에 붙인 `/api` 프리픽스 때문에 브라우저에 보이는 요청 경로(`/api/auth/refresh`)가 백엔드 쿠키의 `Path=/auth` 스코프와 어긋나 쿠키가 아예 전송되지 않았음. 프리픽스를 제거해 백엔드 라우트와 프록시 경로를 정확히 일치시켜 해결.
- **매니저/dev 로그인 시 대시보드에서 "일정을 불러오지 못했습니다".** `GET /schedules`는 매니저/dev가 호출할 때 항상 `student_id`를 요구하는데(본인 달력이어도), 프론트에서 이를 빠뜨림. `DashboardPage`가 항상 `student_id`를 명시적으로 넘기도록 수정.
- **Docker Compose로 띄우면 프론트 컨테이너가 백엔드에 연결 실패(`ECONNREFUSED`).** 컨테이너 안에서 `localhost`는 프론트 컨테이너 자신을 가리켜 백엔드에 닿지 않음. `BACKEND_ORIGIN=http://backend:8000` 환경변수로 프록시 대상을 서비스명으로 전환.
- **Docker(Windows) 안에서 코드를 고쳐도 반영이 안 됨.** Docker Desktop(Windows)의 바인드 마운트가 호스트 쪽 파일 변경 이벤트를 컨테이너로 전달하지 못해 Vite의 파일 감시가 아예 동작하지 않던 문제. 개발 편의 저해뿐 아니라 "고쳤는데 왜 그대로냐"는 혼선까지 유발 — `server.watch.usePolling`을 활성화(도커에서만)해 해결.
- **Agent가 뽑아낸 마감 시각이 실제로 9시간(또는 날짜까지) 밀려서 저장됨.** 실사용 중 "서비스 기획 최종발표, 오후 7시~9시"를 넣었더니 결과가 다음날 새벽 4시로 나온다는 리포트로 발견. 원인은 분석 프롬프트가 "본문의 시각이 어느 타임존이냐"를 전혀 알려주지 않아 LLM이 숫자(19시)는 맞게 뽑으면서 UTC로 잘못 태깅한 것(KST는 UTC+9라 9시간 밀림). 프롬프트에 "본문 시각은 Asia/Seoul(UTC+9) 기준이며 변환하지 말고 +09:00 오프셋으로 그대로 출력하라"를 명시해 해결, 실제 LLM 재호출로 정확한 값 확인. 이미 승인되어 실제 `Schedule`로 반영된 과거 건들은 이번 수정 대상에서 제외(운영 데이터라 별도 정정 필요 시 수동 처리).
- **테스트로 확인 못 하고 지나갈 뻔한 문제들.** `make_user` 픽스처가 `nick_name` 오버라이드를 지원하지 않아 한글 정렬 테스트를 못 짤 뻔했고(픽스처에 옵션 추가), 관리자/에이전트 페이지의 라우트 순서(`/users/{id}` vs `/users/all` 등 고정 경로) 충돌도 초기에 유의해서 피함.
