## 원 계획 대비 변경된 결정사항

### `DevRoute`는 삭제하지 않고 미사용 상태로 보존

`/admin/users`, `/admin/agent`를 전부 `ManagerRoute`로 옮기면서 `DevRoute`를 참조하는 곳이 없어져 삭제하려 했으나, "나중에 두 페이지의 권한이 다시 나뉠 수도 있다"는 이유로 파일은 남겨두기로 함. 코드베이스 orphan 정리 원칙의 예외.

### 계정 삭제 버튼을 매니저에게 숨기지 않고, 클릭 시 이유를 알려주는 방식으로 결정

처음엔 "권한 없으면 버튼 자체를 안 보여주기"가 기본값이었으나, 명시적으로 "삭제 버튼도 보이게는 하는데 권한이 필요하다는 식으로 뜨게 해"라는 요청에 따라 변경. 매니저가 계정 관리 화면에 들어올 수 있게 되면서(권한 변경은 가능) 삭제만 안 되는 이유를 즉시 알 수 있게 하려는 의도.

## 트러블슈팅

- **첫 커밋 메시지가 실제 diff 범위를 반영하지 못함.** 여러 차례의 소규모 요청(브랜딩, 삭제 확인, 정렬, 테두리, 크기 확대, TODO 레이아웃)이 커밋되지 않고 쌓인 상태에서 "Agent 검토 권한 확대"만 커밋했는데, 실제로는 그 전 변경사항들이 전부 같은 커밋에 같이 들어가 있었음(파일이 겹쳐서 분리 커밋이 어려웠음). 이미 push된 상태였으나 다른 사람이 pull하지 않은 것을 확인 후 `git reset --soft`로 두 커밋(기능 커밋 + 별도 문서 삭제 커밋)을 합쳐 diff와 정확히 일치하는 메시지로 재작성, `git push --force-with-lease`로 덮어씀.
- **Amend 대상 착각.** 커밋 메시지를 고치려다 `git commit --amend`가 의도한 커밋이 아니라 그 바로 위에 있던(별개의) 문서 삭제 커밋을 잘못 수정하는 실수가 있었음. `git reset --soft`로 두 커밋 모두를 워킹트리로 되돌려 하나로 재정리해 해결.
