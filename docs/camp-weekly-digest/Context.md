# 카테캠 주간 트래커 — 논의 정리

## 문제 배경
카카오 테크 캠프는 디스코드 + 노션을 사용 중인데, 할 일이 많아서 PR 등록/학습일지 등록을 빼먹는 경우가 잦음. 디스코드 채팅 내역과 노션의 특정 페이지를 읽어서 요약 + "이번 주 할 것" 정리를 해주는 웹사이트를 만들어 이를 방지하고자 함.

## 스코프 결정
- **대상**: 나 개인이 아니라 **캠프 전체**(팀/조 단위 이상)를 대상으로 하는 도구로 결정.
- 이유: 개인용보다 훨씬 유용하지만, 그만큼 권한 요구사항이 커짐 (아래 참고).

## 권한 조사 결과

### 디스코드
- **셀프봇(개인 계정 토큰으로 자동화) 절대 금지** — Discord Developer Policy / 커뮤니티 가이드라인 위반, 적발 시 계정 정지 위험. 우회 방법 없음.
- 정식 봇을 서버에 추가하려면 그 사람이 **"서버 관리(Manage Server)" 권한**을 가지고 있어야 함 → **운영진만 가능**, 일반 참가자는 봇 자체를 초대할 수 없음.
- 봇이 서버에 들어간 뒤에도, 특정 채널을 읽으려면 그 채널에 대해 `VIEW_CHANNEL` + `READ_MESSAGE_HISTORY` 권한을 별도로 받아야 함.
- **결론: 디스코드 쪽은 운영진 협조 없이는 불가능.** 나(사용자)는 현재 이 권한 없음.

### 노션
- 노션 권한은 두 단계로 분리됨:
  1. **인테그레이션(연동 앱) 생성** — `Settings → Connections → Develop your own connections → + New connection`. **오직 Workspace Owner만 가능.** Member는 이 화면 자체가 막히거나, 워크스페이스 선택 드롭다운에 대상 워크스페이스가 안 뜸.
  2. **특정 페이지를 이미 만들어진 인테그레이션과 공유** — 그 페이지에 대한 "완전한 액세스(편집 권한)"가 있는 사람이면 누구나 가능 (`페이지 [...] → Connections → 연동 이름 검색`). 이건 Member도 가능.
- 인테그레이션 생성 시 권한 세분화 가능: Content(읽기 전용/쓰기 전용/삽입만), User Data(접근 안 함/이메일 제외 읽기/이메일 포함 읽기). 이번 용도는 **Content: 읽기 전용, User Data: 접근 안 함**이면 충분.
- 역할 확인 방법: `Settings → Members`(또는 `People`)에서 본인 이름 옆 role 라벨 확인 (Workspace owner / Member / Membership admin(Enterprise 전용) / Guest).
- **결론: 나는 현재 "페이지 생성 권한"(= Member로 추정)만 있고, 인테그레이션 생성 권한(Owner)은 없음.** 확인 필요하면 위 방법으로 직접 체크.

## 현재 결정 사항
**두 권한(디스코드 봇 추가, 노션 인테그레이션 생성) 모두 없는 상태로 우선 MVP를 만들어보기로 함.**
- 운영진에게 권한을 요청하기 전에, 실제로 동작하는 데모를 먼저 만들어서 설득 근거로 쓰는 전략.
- MVP는 본인이 이미 접근 가능한 범위(본인이 볼 수 있는 채널/본인이 만든 노션 페이지 등)로 스코프를 좁혀서 시작.

## 대략적인 아키텍처 (초안)
```
디스코드 채널(PR/학습일지) ─┐
                          ├─ 주기적 수집(cron) → 요약/미제출자 판별 (Claude API) → 웹 대시보드
노션 페이지(제출 현황 등) ──┘
```
- 백엔드: 디스코드 메시지 + 노션 페이지를 주기적으로 가져와 구조화 저장, 누가 PR/학습일지를 언제 올렸는지 매칭
- "미제출 판별"은 순수 규칙 기반(날짜/키워드 매칭)으로도 상당 부분 가능 — LLM은 자연어 요약 파트에 집중하는 게 안정적일 수 있음
- 프론트: 주간 대시보드 (권한 확장 시 조원 전체 보기로 확장 고려)

## 다음 세션에서 할 일 (열린 질문)
1. MVP 스코프를 정확히 확정 — 어떤 채널/어떤 노션 페이지까지 "본인 접근 가능 범위"인지 점검
2. 노션: `Settings → Members`에서 본인 role 실제로 확인
3. MVP 기술 스택 결정 (백엔드 언어/프레임워크, 호스팅 방식)
4. 데모 완성 후 운영진에게 전달할 권한 요청 문구 작성 (읽기 전용 봇 + 특정 페이지 한정 인테그레이션이라는 점 강조)
